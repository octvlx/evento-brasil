## Fixed findings

| Severity | Finding | Correction and evidence |
| --- | --- | --- |
| CRITICAL | A refund followed by a chargeback (or the reverse) could record two full financial reversals for one payment. | Mutually exclusive terminal-state guards in `payments.ts`; regression tests preserve the original ledger and payment state on conflicting terminal updates. |
| MEDIUM | Public event lists queried commission rules once per event. | Shared batched commission resolver; the catalogue regression checks one commission query for multiple events and preserves event → organization → platform precedence and active-date boundaries. |
| MEDIUM | Hidden ticket lots were ignored when calculating event capacity and half-price quota. | Hidden lots count toward committed stock and quotas but stay out of public ticket selection and prices. |
| MEDIUM | Cards could advertise availability outside a ticket lot's sale window. | Availability considers both event and lot sale windows. |
| MEDIUM | Non-finite, fractional, or excessively large page numbers could reach Prisma as invalid pagination offsets. | Normalize invalid pagination before database calls; regression coverage includes Infinity, NaN, fractions, negatives, and oversized offsets. |

## Loading and tooling improvements

- Catalogue queries select only card fields, avoiding full event descriptions,
  policies, and organizer-only scalar fields.
- The homepage fetches the five featured cards it actually displays instead of
  fetching six and discarding one. Only the primary card image requests high
  priority; secondary cards use normal lazy loading.
- ESLint excludes generated files, local database artifacts, and nested agent
  worktrees. Application code, scripts, tests, and configuration remain covered.
- Integration fixtures explicitly disconnect their Prisma client after tests.
- `npm run test:e2e:isolated` runs the browser suite with its own temporary
  PostgreSQL database, seeded demo accounts, application port, Next.js build
  directory, and TypeScript configuration. It never seeds the developer database.
  Test emails use the existing console outbox; they are not sent externally.

No business records, historical ledger entries, or audit logs were deleted.
The speed improvements are supported by reduced query counts and selected data;
no before/after page-load timing claim is made.

## Scope and integration

Automated checks cover the repository's TypeScript, lint targets, existing unit,
integration, and browser suites. Source review focused on catalogue/commission
queries, inventory visibility, payment transitions, authentication/authorization,
protected PDF/wallet routes, scheduled maintenance, and test infrastructure.
This is a targeted engineering audit, not a claim that every possible defect
has been eliminated or that external providers are production-certified.

Public catalogue prices still use the checkout's authoritative fee calculation.

inventory, or financial state. The financial changes stay inside the existing
transactional payment service rather than introducing a competing service.
